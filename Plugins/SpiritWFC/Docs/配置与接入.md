# WFC 配置、父类与接入说明

更新：2026-10-26。插件：`SpiritWFC`，引擎：UE 5.6。先使用插件示例地图，不改变原项目首页或三个玩法关卡。

首次使用建议先看[从零到生成地图完整教程](从零到生成地图完整教程.md)，本文作为参数与接口手册。

## 1. 三个 C++ 父类和一个纯算法类

| 类型 | 继承 | 用途 | 推荐使用方式 |
|---|---|---|---|
| `AWFCMapGenerator` | `AActor` | 求解、分组加载模型、生成 HISM，保留最后成功地图 | 蓝图继承或拖入示例生成器 |
| `UWFCTileSet` | `UDataAsset` | 模块、接口、权重、楼层与资源清单 | 新建此类型的数据资产 |
| `UWFCBlueprintLibrary` | `UBlueprintFunctionLibrary` | 蓝图/Python 单独求解和校验数据 | 使用 `Solve WFC`、`Validate WFC` 节点 |
| `FWFCSolver` | 普通 C++ 类 | 无 World 的约束求解与复核 | `FWFCSolver::Solve/ValidateSolution`；不继承 |

`FWFCGenerationSettings`、`FWFCCellPlacement`、`FWFCGenerationResult`、`FWFCTileDefinition`、`FWFCSockets` 和 `FWFCPinnedCell` 是结构体，不是场景父类。

## 2. 生成器配置

| 字段/操作 | 作用 |
|---|---|
| `TileSet` | 当前规则与静态网格资源。原生空生成器需手动指定 |
| `Settings.Mode` | `Planar` 四邻接、强制一层；`Volume` 六邻接 |
| `Width / Depth` | 每轴 1～64，整个网格最多 4096 格 |
| `Layers` | 立体模式为 1～3；输入第四层会返回 `InvalidInput` |
| `Seed` | 随机种子。相同规则顺序、参数、版本和种子可复现 |
| `MaxRestarts` | 矛盾/不连通后的重启次数，0～32；总尝试最多为它加一 |
| `MaxPropagationSteps` | 所有尝试共享的传播工作预算，1～20000000；默认 2000000 |
| `ConstrainHorizontalBoundary` | 开启后，外缘接口必须等于 `HorizontalBoundarySocket` |
| `ConstrainVerticalBoundary` | 仅立体模式使用，约束最底层向下、最顶层向上的接口 |
| `BottomBoundarySocket / TopBoundarySocket` | 默认 `Ground / Sky` |
| `RequireConnectedWalkableCells` | 必须存在且只有一个格子可通行连通分量；否则重试 |
| `PinnedCells` | 固定入口、出口、楼梯或特殊建筑。坐标从 0 开始 |
| `EnableCollision` | HISM 是否阻挡；示例网格使用复杂碰撞作为简单碰撞 |
| `AffectNavigation` | 组件是否参与导航；不会自动创建导航边界体或烘焙导航 |
| `GenerateOnBeginPlay` | 默认关闭。开启后开始游戏时同步生成 |
| `GenerateMap()` | 成功后替换显示地图并返回 true；失败保留旧地图 |
| `ClearGeneratedMap()` | 仅销毁该生成器的实例组件，清空显示结果 |
| `GetGeneratedInstanceCount()` | 当前显示的格子模型实例总数 |

### 平面示例

`BP_WFC_Planar`：12×12，一格 300 cm，横向边界 `Ground`，开启连通性检查。固定 `(0,0,0)` 为庭院、`(6,6,0)` 为道路交叉口。

`DA_WFC_Planar` 使用：庭院、直路、转角、尽头、十字路、建筑墙/角/门和喷泉。地面边缘为 `Ground`，道路出口为 `Road`，两种接口都可供角色格子图通行。建筑格子标为不可通行；这些建筑是布局占位模块，并非可进入的完整房屋。

横向接口必须匹配，所以道路出口不会直接接到普通地面接口；道路允许多个局部路网，因为整个庭院地面也能行走。本例不额外保证“所有道路只形成一条网络”。道路目前只是地板色块占位。

### 三层示例

`BP_WFC_ThreeLayers`：8×8×3，一格 300 cm，关闭横向边界封闭，底/顶边界为 `Ground/Sky`。固定 `(3,3,0)` 为 `BottomStair`。

`DA_WFC_Volume`：底层、中层、顶层地板/厅堂与楼梯，另有一层专用地板和顶层屋顶。普通上下支撑为 `Floor`；真正跨层通行为 `Stair`。固定一个底层楼梯会通过上下接口传播出同列中、顶层楼梯。

该规则也能生成 1 或 2 层：2 层不选中层模块；1 层选 `SingleFloor`。把三层示例改成一层时，要删除原来的 `BottomStair` 固定格，改为 `SingleFloor` 或留空，否则固定楼梯与顶界 `Sky` 冲突。

## 3. 模块数据资产

在内容浏览器新建“数据资产”，类型选 **WFC Tile Set**，或者复制现成资产。

| `FWFCTileDefinition` 字段 | 配置含义 |
|---|---|
| `TileId` | 唯一、非空、稳定 ID。禁用条目也不能重名 |
| `Enabled` | 是否进入候选集 |
| `Weight` | 正有限数；约束相同的情况下影响抽取概率，不是最终数量配额 |
| `AllowedYawQuarterTurns` | 0/1/2/3 对应 0/90/180/270°。不得重复 |
| `Sockets` | 本地方向 `+X/-X/+Y/-Y/Up/Down` 六个接口名字；不能用 `None` |
| `MinLayer / MaxLayer` | 绝对楼层索引 0～2 |
| `BottomLayerOnly / TopLayerOnly` | 按当前生成层数判定底层/顶层；单层时二者同时成立 |
| `Walkable` | 此格是否进入可通行图；不会自动推断模型内部是否有门 |
| `Mesh` | 静态网格软引用；求解可为空，实际渲染时必须可加载 |
| `MeshTransform` | 模块局部位置/旋转/缩放，之后再施加格子旋转和平移 |
| `Materials` | 可选材质覆盖，按网格材质槽顺序；填入的引用必须能加载 |

资产的 `CellSize` 为正有限厘米向量。`TraversableSockets` 明确列出允许穿过的接口，例如 `{Door, Stair}`。`Floor` 只做支撑时不要放进去，否则会把楼板当楼梯。

旋转后 `+X` 指向 `+Y`，这是 UE 正 Yaw 的 90°。四个水平接口一起旋转，上/下名字保持不变。因此方向敏感的螺旋楼梯，需分别制作固定方向模块、设置对应的上/下接口并将旋转限制为 0；本版不会自动识别楼梯开口朝向、镜像接口或多个子接口。

同名接口兼容，`Closed` 同样可以与 `Closed` 连接，但它默认不允许通行。`FName` 比较不区分字母大小写，建议统一使用一致的命名格式。不存在通配接口。

启用模块展开旋转后最多 256 个变体。一个模块的权重会均分到其全部旋转，避免配置四个旋转就获得四倍总概率。

## 4. 自己的美术模块怎么准备

1. 约定统一格子、落脚高度、水平中心和接口位置，先做少量直路、拐角、墙、门与上下楼梯。
2. 把尺寸、Pivot 和旋转统一，再配置接口。接口名字由设计者定义，系统不会根据模型轮廓自动分析。
3. 本轮导入模型原始标准格为 2 m，保留源格子 Pivot；平地在 Pivot 下方 0.6 m。示例缩放 1.5、Z 偏移 +90 cm，对应 300 cm 格子。
4. 新模型无需照搬 +90 cm：根据自身 Pivot 设置 `MeshTransform`。带厚度/台阶的建筑必须检查相邻格子实际地面高度。
5. 楼梯要验证人物净高、入口方向、步高、楼层连接和碰撞。示例继承源模块几何，但没有迁移 Unity 原项目完整原型规则；当前规则是本项目自建的教学规则。

HISM 每个实际使用的模块定义创建一个组件，同模块不同格子/旋转创建实例，避免每格一个 Actor。格子坐标先乘 `CellSize`，再叠加生成器 Actor 的变换。

## 5. 蓝图事件和 UI/玩法预留

最简单流程：`Generate Map → Branch(返回值) → 读取 Displayed Result → 配置出生点/敌人/传送门`。

也可以绑定 `OnGenerationFinished(Result)`，检查 `Status == Success` 再继续。事件为同步调用；应在生成前绑定，不要在回调里反复调用 `GenerateMap` 造成递归。

`Solve WFC(TileSet, Settings)` 只生成布局数据，不加载模型或修改场景；可以给设计预览、种子筛选和后续服务器生成使用。`Validate WFC` 可独立检查加载或编辑后的布局。

结果提供 `Cells`、`Dimensions`、`RequestedSeed/EffectiveSeed`、`Attempts`、`Decisions`、`PropagationSteps`、`WalkableComponents`、`FailedCell`、消息和耗时。格子数组按 **X 最快、再 Y、再 Z** 排序：`index = x + width*(y + depth*z)`。

`LastResult` 是最近尝试，失败时可能与当前画面不同；读画面数据使用 `DisplayedResult`。失败不会发布半张地图。求解成功但模型/材质失效也会返回失败，保留旧实例。

保存随机地图时，后续应同时存种子、规则版本/内容哈希、设置和固定格；单独存种子不能保证规则修改后地图仍相同。当前不写入原有角色存档，也没有注册随机地图到 N 键传送菜单。

## 6. 错误处理与建议

C++ 调用方在自己的 Build.cs 中添加 `SpiritWFC` 依赖。仅在 `.cpp` 使用时加到 `PrivateDependencyModuleNames`；如果公共头文件暴露本插件的类型，则加到 `PublicDependencyModuleNames`。再包含 `WFCSolver.h` 或 `WFCMapGenerator.h`。仅使用示例蓝图不需要改原游戏模块的 Build.cs。

```cpp
#include "WFCSolver.h"
// TileSet 和 Settings 由调用方持有/配置；不需要提供 World。
const FWFCGenerationResult Layout = FWFCSolver::Solve(TileSet, Settings);
if (Layout.Status == EWFCResultStatus::Success)
{
    // 使用 Layout.Cells；场景实例化也可直接交给 AWFCMapGenerator。
}
```

| 结果 | 常见原因与处理 |
|---|---|
| `InvalidInput` | 空 TileSet、无候选、重复 ID、无效权重/旋转、超过层数/格数、固定格越界；渲染阶段也可能是资源缺失 |
| `Contradiction` | 某格候选为空；检查边界、楼层标签、邻接接口和固定模块是否互相冲突 |
| `BudgetExceeded` | 传播达到全部尝试共享预算；先减格子/旋转，再考虑适度增加预算 |
| `Disconnected` | 局部拼接完成但可通行图不是一个分量；补门、固定楼梯或调整不可通行比例 |
| `Success` | 已通过数据规则和所要求的格子连通性检查 |

先用 8×8 或 12×12 调规则。下一阶段建议先制作一套符合角色碰撞与步高的正式建筑模块，完成导航与角色通行验收，再接入出生点、敌人生成与地图存档。大型地图的后台任务、分块/流式生成、回溯和跨地块约束是后续扩展；当前为有上限的同步全图求解。
