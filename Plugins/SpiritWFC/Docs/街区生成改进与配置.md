# 街区生成 v0.2：布局与建筑效果改进

## 从哪里看新效果

开启内容浏览器“显示插件内容”，进入 `/SpiritWFC/Settlement/Maps`：

- `L_WFC_Settlement_Planar`：14×14 的单层街区，完整房屋、相连主街/环路和中央广场。
- `L_WFC_Settlement_ThreeLayers`：相同尺度，一到三层建筑交错，房屋上方和街道上空留白。

选中 **WFC Settlement - Generate Map**，修改 Seed 后点 **Generate Map**。对应蓝图在 `Settlement/Blueprints`，规则资产为 `Settlement/Data/DA_WFC_Settlement`。早期 `/Samples` 地图保留为原始 WFC 教学样例。

## 原来效果差在哪里

早期样例验证的是格子约束：道路复用地板换色，墙、拐角和门被独立随机摆放，不能组成完整房屋；立体样例为了检查楼梯接口，铺满了三层地板。它可以通过接口检查，但没有街区尺度的空间组织，也没有完整建筑轮廓。

v0.2 改为两步：**先用程序规则规划街区，再用 WFC 选取符合规划的模块并校验连接**。这是一套混合方案；环路、主街和广场由规划器产生，不宣称它们是纯局部 WFC 自行推导出的城市设计。

## 实际改了什么

| 改进 | 当前行为 |
|---|---|
| 道路组织 | 单一连通的环路与两条主街；主街位置随种子变化 |
| 中央广场 | 固定保留 3×3 格，建筑不占用这些格子 |
| 建筑用地 | 在临街候选地块按密度选择；房屋入口朝向相邻街道 |
| 完整模型 | 房屋包含地板、四面墙、门窗、木构和坡屋顶；道路有铺装与路沿 |
| 变高建筑 | 每栋选择一到三层；同栋楼层朝向一致，通过 Stair 接口连接 |
| 上空留白 | 用不渲染的 Air 模块表示，不再整层铺满楼板 |
| 几何一致 | 专门用非对称模型验证 FBX 坐标，修正 Y 轴转换，避免接口和门朝向相反 |
| 材质与细节 | 统一的草地/石材/灰墙/木构/瓦色，补齐 UV 与小倒角，减少杂乱占位感 |

建筑套件由本项目的 Blender 脚本制作，属于简洁占位美术。原下载建筑模型继续保留在 Samples，来源与许可不变。

## 调整方式

生成器 `Settings`：

| 字段 | 建议 |
|---|---|
| `Layout Preset` | 选 `Settlement` 启用街区规划，`Free` 保留早期自由 WFC |
| `Width / Depth` | 新预设至少 9×9，示例 14×14；仍受总格数 4096 限制 |
| `Mode / Layers` | Planar 固定一层；Volume 可为一到三层 |
| `Seed` | 改变主街位置、房屋分布、高度和兼容外观变体 |
| `Building Density` | 0～1，对“临街候选地块”的占用概率；不是整张图的建筑面积比例 |
| `Constrain Horizontal Boundary` | 此示例关闭，外围地面/上层空气由规划器约束 |
| `Pinned Cells` | 默认空；额外固定格仍需与宏观规划兼容 |

建议先把密度调到 0.6～0.85 范围观察疏密。0 会得到没有房屋的道路/广场预览。此建议只针对当前占位套件，不是通用性能指标。

规则资产一格为 `(600,600,360)` cm。新模型 Pivot 已在地面，`MeshTransform` 使用单位变换；不要照搬旧下载套件的 1.5 缩放和 +90 cm 偏移。

## 新接口与标签

`FWFCLayoutPlanner::Build` 产生逐格的 `FWFCCellRule`：坐标、RequiredTag、可选朝向。`UWFCBlueprintLibrary.PlanWFCLayout` 可在蓝图读取规划数据。求解器在原固定格条件上，继续和这些语义条件取交集，再执行原有熵选择、传播和连通性复核。

TileSet 每项新增：

- `Tags`：规划器识别的语义标签。
- `Render Mesh`：关闭时仍参与约束，但不加载模型或生成实例；Air 使用此配置，同时 Walkable 关闭。

当前标签：

| 标签 | 含义 |
|---|---|
| `Ground` | 底层普通地面 |
| `Road_00`～`Road_15` | 道路四方向连接的位掩码 |
| `Plaza_00`～`Plaza_15` | 广场与道路网络相接，视觉使用统一广场铺装 |
| `House` | 单层完整房屋，Down=Ground、Up=Sky |
| `Base` | 多层建筑底层，Down=Ground、Up=Stair |
| `Middle` | 中间层，Down/Up=Stair |
| `Top` | 顶层加屋顶，Down=Stair、Up=Sky |
| `Air` | 未被建筑占用的上层空间，Down/Up=Sky |

道路掩码顺序为 `+X=1、-X=2、+Y=4、-Y=8`。例如 Road_03 是 X 方向直路。宏观规划确定道路接向后，WFC 仍检查相邻 Road/Ground 接口一致；同角色的兼容房屋外观由权重选择。

房屋原始正面是 UE 本地 -Y，规划器把它旋转到临街方向。同栋建筑的上层沿用同一旋转，避免上下楼梯相反。旋转不能只改网格外观而不改模块接口。

有了不渲染的 Air 后，`DisplayedResult.Cells.Num()` 表示逻辑格数，`GetGeneratedInstanceCount()` 表示实际可见实例数；立体预设中两者通常不同。

## 制作与验证入口

- `Scripts/WFC/build_settlement_kit.py`：Blender 后台制作 27 个模型，含一个坐标校验模型。
- `Scripts/WFC/configure_settlement_samples.py`：编辑器导入材质/模型、创建新示例；已有地图默认保留。
- `-WFCReimportKit`：显式重新导入新套件模型。
- `-WFCRebuildSettlement`：显式重建本预设拥有的示例 Actor，发现未标记的用户 Actor 会中止。
- `Scripts/WFC/verify_settlement_samples.py`：编辑器检查实际资产、种子、密度变化和实例保存。
- `Scripts/WFC/render_settlement_preview.py`：使用 UE 实际生成的布局 JSON 离线渲染预览；不是游戏截图。

## 仍需人工验收

现阶段改善的是布局组织和占位建筑完整性。楼梯采用相接的 U 型台阶与楼板开口，但人物胶囊、导航 Agent、门窗净宽、上楼和战斗空间仍要手动运行验收。算法通过不等于角色或 AI 已完成通行测试。

后续替换正式美术时，保留地块尺寸、门朝向、楼层高度和上下开口规范。更自由的街道形状、多格建筑预制件、房间用途、敌人/宝箱分布及运行时导航完成协调，仍属于下一阶段。
