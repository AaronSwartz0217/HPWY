## 一、先分清三个对象

| 你会操作的对象 | 可以理解成 | 当前对应内容 |
|---|---|---|
| 静态网格 `Static Mesh` | 一块积木的外观 | 地板、墙、屋顶、楼梯 |
| 规则资产 `WFC Tile Set` | 积木清单和拼接说明 | `DA_WFC_Planar`、`DA_WFC_Volume` |
| 场景生成器 `WFC Map Generator` | 按规则摆积木的机器 | `BP_WFC_Planar`、`BP_WFC_ThreeLayers` |

每种建筑积木先登记到规则资产里，再由一个生成器生成整张地图。普通模块不用各自建立 Actor 蓝图；生成器会把重复网格作为 HISM 实例批量摆放。宝箱、敌人、传送门等需要独立逻辑的对象，适合在布局成功后另行生成 Actor。

对应程序类型：`UWFCTileSet` 存规则，`AWFCMapGenerator` 放场景，`UWFCBlueprintLibrary` 提供独立数据求解；底层 `FWFCSolver` 不需要场景 World。

## 二、找到并打开现成示例

1. 打开工程 `CrashCourse.uproject`。本模块已完成编译；同步源码到新电脑时，应先安装 UE 5.6 及对应 C++ 工具链，再编译工程。
2. 打开内容浏览器或内容抽屉，在其设置中启用 **Show Plugin Content / 显示插件内容**。
3. 在插件内容中找到 SpiritWFC。不同语言下显示名称可能有区别，实际资源路径始终以 `/SpiritWFC` 开头。
4. 进入 `/SpiritWFC/Samples/Maps`，双击地图。

| 地图 | 用来学习什么 |
|---|---|
| `L_WFC_Planar` | 12×12 单层庭院、道路和建筑占位 |
| `L_WFC_ThreeLayers` | 8×8×3，地板支撑与楼梯列连接 |
| `L_WFC_ModelGallery` | 单独查看下载并转换的 12 个建筑模块 |

如果搜不到地图，先检查显示插件内容，再在“编辑 → 插件”里搜索 `SpiritWFC`，确认已启用。资源路径对应磁盘目录 `Plugins/SpiritWFC/Content/Samples`。

## 三、重新生成第一张地图

以 `L_WFC_Planar` 为例：

1. 在世界大纲中选中名称以 **WFC Generator** 开头的 Actor。
2. 在详情面板搜索 `WFC`，展开 `Settings`。
3. 第一次先只改 `Seed`，例如由 `20261026` 改成 `12345`。
4. 点击 **Generate Map**。这是编辑器按钮，不需要启动游戏。
5. 展开 `Last Result`，检查 `Status` 为 `Success`；展开 `Displayed Result → Cells`，应有 144 个格子。
6. 用相同种子再次生成，在规则和参数不变的情况下，布局应保持一致。
7. 点击 **Clear Generated Map** 可以清除该生成器的网格实例；再点 Generate Map 可以重建。

地图不是自动摆在生成器两侧：格子中心从生成器位置开始，沿本地 +X、+Y 和 +Z 增长。选中生成器后可在视口按 `F` 聚焦，再拉远观察整图。

**先不要随意缩小 Width/Depth。** 平面样例固定了 `(6,6,0)` 的十字路和 `(0,0,0)` 的庭院。改成 4×4 时，前一个固定坐标已经越界。练习小尺寸前，先把 `Settings → Pinned Cells` 数组清空，或者把这些坐标改到新范围内。

出现失败时：

- `Last Result` 说明这一次为什么失败。
- `Displayed Result` 仍代表上次成功显示的地图。

因此，画面还在不代表最新一次生成成功。处理好错误后再重新生成。

## 四、建立自己的文件夹和地图

推荐在项目内容中建立自己的练习目录，方便日后替换正式资源：

```text
/Game/ProceduralGeneration/WFC/
    Blueprints/
    Data/
    Maps/
    Meshes/
    Materials/
```

最快的方式是复制现成资源：

1. 复制 `/SpiritWFC/Samples/Data/DA_WFC_Planar` 到自己的 `Data`，命名 `DA_WFC_MyPlanar`。
2. 复制 `/SpiritWFC/Samples/Blueprints/BP_WFC_Planar` 到自己的 `Blueprints`，命名 `BP_WFC_MyPlanar`。
3. 打开自己的蓝图，选择 **Class Defaults / 类默认值**，将 `Tile Set` 指向 **DA_WFC_MyPlanar**，编译并保存。
4. 新建一个空白关卡，保存为 `/Game/ProceduralGeneration/WFC/Maps/L_WFC_MyPlanar`，添加自己需要的基础照明。
5. 将自己的蓝图拖入关卡，位置先设为 `(0,0,0)`、旋转 0、缩放 1。
6. 点击 Generate Map，确认成功后保存关卡。

复制蓝图并不会自动把它内部引用的规则也换成副本，第三步必须手动完成。已经摆进场景的 Actor 也可能有实例覆盖值，最终要核对选中 Actor 的 `Tile Set`。

如果更喜欢从父类开始：新建蓝图类 → 展开全部类 → 搜索 **WFC Map Generator**。空父类没有指定规则，必须自己配置 Tile Set 和 Settings。下一章给出一套最小可用配置。

## 五、从零配置一套保证容易理解的平面规则

这一练习先让每格都能正确出现，再逐步增加道路约束。

### 5.1 建立规则资产

在自己的 `Data` 文件夹新建“数据资产”，类型选择 **WFC Tile Set**，命名 `DA_WFC_FirstGrid`。配置：

| 字段 | 值 |
|---|---|
| `Cell Size` | `(300,300,300)`，单位厘米 |
| `Traversable Sockets` | 添加一个名字 `Ground` |
| `Tiles` | 添加一项 |

展开这项 Tile：

| 字段 | 值 |
|---|---|
| `Tile Id` | `Floor_A` |
| `Enabled` | 开启 |
| `Weight` | `1` |
| `Allowed Yaw Quarter Turns` | 数组只留 `0` |
| `Sockets → Positive X / Negative X / Positive Y / Negative Y` | 全部 `Ground` |
| `Sockets → Up / Down` | 分别 `Sky / Ground` |
| `Min Layer / Max Layer` | `0 / 2` |
| `Bottom Layer Only / Top Layer Only` | 都关闭 |
| `Walkable` | 开启 |
| `Mesh` | `/SpiritWFC/Samples/Meshes/SM_WFC_Floor` |
| `Mesh Transform → Location` | `(0,0,90)` |
| `Mesh Transform → Rotation` | 全 0 |
| `Mesh Transform → Scale` | `(1.5,1.5,1.5)` |
| `Materials` | 添加样例 `M_WFC_Stone`，或暂时留空使用网格原材质 |

这里的 +90 cm 是当前下载地板的 Pivot 修正。它不是所有模型都需要的偏移，换自制地板时要根据实际 Pivot 调整。

### 5.2 配置生成器

把空的 WFC Map Generator 蓝图放入自己的关卡，设置：

| 字段 | 值 |
|---|---|
| `Tile Set` | `DA_WFC_FirstGrid` |
| `Settings → Mode` | `Planar` |
| `Width / Depth` | `4 / 4` |
| `Seed` | `100` |
| `Constrain Horizontal Boundary` | 开启 |
| `Horizontal Boundary Socket` | `Ground` |
| `Require Connected Walkable Cells` | 开启 |
| `Pinned Cells` | 清空 |
| `Generate On Begin Play` | 关闭 |

点击 Generate Map，应得到 **16 格**地面，Status 为 Success，可通行图分量为 1。

只有一种候选时，换种子不会改变布局，这是正常结果。想看到不同组合，可以复制 Tile 为 `Floor_B`，保留相同接口，换一种材质；两个 ID 必须不同。再生成时就有了随机选择。

### 5.3 理解接口，而不是只背名字

`Ground`、`Road`、`Door`、`Closed` 都是设计者定义的名字。判断相邻兼容时，系统比较两块积木相对的面：

```text
A 的 Positive X  对  B 的 Negative X
A 的 Positive Y  对  B 的 Negative Y
下层的 Up       对  上层的 Down
```

名字一致才能连接。边界开启时，朝地图外面的面还必须满足边界名字。

`Closed` 不是特殊的“禁止相邻”指令：Closed 可以和 Closed 拼起来，只是默认没有加入通行接口集合。接口兼容解决“能拼”，`Walkable` 和 `Traversable Sockets` 解决“规则上能走”。

## 六、增加道路、建筑和指定位置

### 6.1 给道路配置出口

可以在自己的最小规则中追加下表；地面模型先复用 Floor，材料用 `M_WFC_Road`，网格变换沿用上一章。

| Tile Id | +X | -X | +Y | -Y | 允许旋转 |
|---|---|---|---|---|---|
| `Floor_A` | Ground | Ground | Ground | Ground | `[0]` |
| `RoadStraight` | Road | Road | Ground | Ground | `[0,1]` |
| `RoadCorner` | Road | Ground | Road | Ground | `[0,1,2,3]` |
| `RoadEnd` | Road | Ground | Ground | Ground | `[0,1,2,3]` |
| `RoadCross` | Road | Road | Road | Road | `[0]` |

所有项的 Up/Down 仍为 Sky/Ground、Walkable 开启；`Traversable Sockets` 改为 `{Ground, Road}`。建议初始权重依次为 `6、3、2、1、0.4`，之后再观察调整。

`0/1/2/3` 表示 `0/90/180/270°` 的 Yaw。生成器会同时旋转几何和四个水平接口。直路只需要两个不同朝向，因此使用 `[0,1]`。

外边界保持 Ground，可以防止道路出口朝向地图外。样例道路目前只用色块表示；正式道路纹理、线条和转角外观需要你换相应模型/材质。

### 6.2 加入建筑

复制一项 Tile，设置新 ID，例如 `HouseBlock_A`，换墙或建筑静态网格，先使用四边 Ground、`Walkable=false`，权重从 `0.2` 开始。此配置把整个格子视为不可进入的建筑占位。

如果建筑实际上允许进入，就需要把门所在面设为通行接口，并让内部空间、地板与邻格的实际门口吻合。不能只把 Walkable 打开，就认为墙内自动有通路。

### 6.3 固定入口和楼梯

展开生成器的 `Settings → Pinned Cells`，新增条目：

```text
Coordinate   = (2,2,0)
Tile Id      = RoadCross
Quarter Turns = -1
```

这会要求指定格子使用 RoadCross。`-1` 允许它配置中的任意旋转；0～3 则指定某个允许的朝向。ID 必须和 Tiles 中一致，坐标必须小于 Width/Depth/Layers。

固定格不是绕过规则的强制摆放：固定一个向外出路的格子，同时要求外边界 Ground，仍可能造成矛盾。入口、出口、楼梯和特殊建筑都可以通过固定格约束，但“入口到出口的专门路径”尚未作为单独业务条件实现。

## 七、配置一到三层立体地图

### 7.1 先使用现成三层规则

复制 `DA_WFC_Volume` 和 `BP_WFC_ThreeLayers` 到自己的文件夹，改蓝图 Tile Set 引用，再放入自己的地图。首次使用：

```text
Mode                          = Volume
Width / Depth / Layers        = 8 / 8 / 3
Constrain Horizontal Boundary = false
Constrain Vertical Boundary   = true
Bottom Boundary Socket        = Ground
Top Boundary Socket           = Sky
Require Connected Walkable Cells = true
Pinned Cells                  = (3,3,0) → BottomStair，旋转 -1
```

应得到 192 格。楼层索引是 **0、1、2**，高度间隔来自 `Cell Size.Z`；本例每层相隔 300 cm。

### 7.2 从零理解六个基本模块

如果只想学习必要规则，可以另建一个 TileSet，只配置下列六种。所有项水平四面均设 `Door`、旋转只留 `[0]`、Walkable 开启，`Traversable Sockets={Door,Stair}`。

| Tile Id | Min/Max Layer | Bottom Only | Top Only | Down | Up | 可用示例模型 |
|---|---|---|---|---|---|---|
| BottomFloor | 0/0 | 是 | 否 | Ground | Floor | SM_WFC_Floor |
| MiddleFloor | 1/1 | 否 | 否 | Floor | Floor | SM_WFC_Floor |
| TopFloor | 1/2 | 否 | 是 | Floor | Sky | SM_WFC_Floor |
| BottomStair | 0/0 | 是 | 否 | Ground | Stair | SM_WFC_StairsLower |
| MiddleStair | 1/1 | 否 | 否 | Stair | Stair | SM_WFC_EnclosedStairs |
| TopStair | 1/2 | 否 | 是 | Stair | Sky | SM_WFC_StairsCeiling |

格子尺寸与下载模型的变换仍使用 `(300,300,300)`、缩放 1.5、Z 偏移 +90 cm。地板权重可从 8 开始，楼梯从 0.25 开始。生成器设置沿用 7.1，并固定一个 BottomStair。

因为 BottomStair 向上是 Stair，正上方就只能接 Down=Stair 的模块；中层继续向上传播，形成同列楼梯。普通 Floor 上下只提供支撑，不会把它当成可穿透的楼板。

这套六模块规则支持 2、3 层。要支持 1 层，再加 `SingleFloor`：Min/Max=0/2、Bottom Only 和 Top Only 同时开启、Down=Ground、Up=Sky、水平全 Door。现成 DA_WFC_Volume 已包含这一项。

### 7.3 改为两层或一层

- 两层：Layers=2，保留底层楼梯固定格；顶层模块会出现在索引 1，不使用 Middle 模块。
- 一层：Layers=1，清除 BottomStair 固定格，保留或添加 SingleFloor；底界和顶界在同一格上同时成立。
- 四层：当前框架直接拒绝，不会偷偷压成三层。

如果移除了所有楼梯，而仍保留三层地板，可能得到 `Disconnected`。这是连通检查在提醒三层彼此不可达。把 `Floor` 加进通行集合会把楼板误当通路，不能用它修复真实的上下楼问题。

## 八、替换自己的模型和材质

1. 把模型导入自己的 Meshes 文件夹，先打开静态网格检查实际尺寸、朝向、Pivot 和碰撞。
2. 选择一格的标准尺寸，例如宽 300、深 300、层高 300 cm。房间中心与边缘门口需遵守同一标准。
3. 在 TileSet 中复制一项，使用新 ID，指定自己的 Mesh，调整 Mesh Transform。
4. 先用只包含该模块的小规则生成 2×2，检查有没有缝、交叠、悬空或地下偏移，再加入复杂连接。
5. 确认实际门口朝向后，填写对应的 +X/-X/+Y/-Y 接口，最后才开放旋转。
6. 给自己的材质启用 **Used with Instanced Static Meshes**，再用于 HISM 模块。五个样例材质已开启。

本轮下载地板宽 200 cm，平面位于 Pivot 的 Z=-60 cm，故采用 `200×1.5=300 cm`、`-60×1.5+90=0`。自制模型若落脚点本来就是 Z=0，就不要照搬 +90 cm。

上下接口在 Yaw 旋转时名字不变。方向敏感的楼梯应按朝向拆成独立 Tile，使用相应上下接口名字并限制旋转，例如一组 `StairEast`，另一组 `StairNorth`。几何旋转可通过各项 Mesh Transform 设置；系统不会自动识别上下开口或镜像模型。

门的净宽、台阶高度、胶囊体净高都需要按实际角色检验，接口名字不能替代尺寸规范。大于一个格子的建筑暂时建议拆成标准模块，或把整体作为一块更大尺度的积木统一设计；当前没有多格占位预制件系统。

## 九、蓝图控制生成和接收结果

### 9.1 最小接线

在自己的生成器蓝图中，Generate Map 的 Target 使用 Self；从关卡蓝图或管理器调用时，传入场景中生成器的引用。

```text
自定义事件 Regenerate
    → Generate Map
    → Branch（Generate Map 的返回值）
        True  → Get Displayed Result → Break WFC Generation Result
        False → Get Last Result → Break WFC Generation Result → Print String(Message)
```

成功后可以读取 Cells、Dimensions、Effective Seed 等字段；`Get Generated Instance Count` 返回可见实例数。只需筛选种子、不想摆场景时，使用 **Solve WFC**；加载旧布局后可用 **Validate WFC** 复核。

### 9.2 在界面按钮中调用

把目标生成器引用传给自己的 Widget。按钮 OnClicked → 调用该引用的 Generate Map → 根据 bool 更新提示。需要先修改种子时，取得 Settings，使用 `Set Members in WFC Generation Settings` 改 Seed，再将结果写回生成器的 Settings，随后调用生成。

### 9.3 使用完成事件

也可以先绑定 `OnGenerationFinished`，在事件里判断 Result.Status==Success，再生成出生点或敌人。直接返回值和完成事件选择一条作为业务入口，避免两边都生成同一批敌人。

当前完成事件是同步的：调用 Generate Map 时就可能触发，所以应先绑定，再发起生成。不要在该回调里再次无条件调用 Generate Map。

### 9.4 什么时候自动生成

预生成地图：在编辑器点 Generate Map，保存关卡，保持 Generate On Begin Play 关闭。

每次开局随机：可开启 Generate On Begin Play；如果还要控制加载界面、出生和 AI，建议保持关闭，由一个管理器按“绑定结果 → 设置种子 → 显式生成 → 等待导航准备 → 放行角色/敌人”协调。当前插件没有导航完成事件或分帧进度回调，需要后续接入。

生成完成只表示规则求解和网格实例化完成，不表示导航已经重建完毕。布局求解是同步过程，不能把 Elapsed Milliseconds 当成整个加载界面的进度。

## 十、配置碰撞、楼梯和导航

### 10.1 先检查实体碰撞

选生成器，确认 Enable Collision 开启；打开静态网格，检查真实碰撞形状。下载样例使用复杂碰撞作为简单碰撞，正式建筑也可以制作简化碰撞，但要保留门洞和楼梯的可走形状。

碰撞和导航开关在创建组件时读取；修改 Enable Collision 或 Affect Navigation 后，应再点 Generate Map 重建组件。

在自己副本中手动运行角色，检查四件事：地板不会掉落、门口可以穿过、楼梯可以上到落脚平台、人物头部不会撞顶。多层地图先只保留一个固定楼梯列检查，再增加随机变体。

### 10.2 给地图添加导航范围

1. 在放置 Actor 面板搜索 **Nav Mesh Bounds Volume**，添加到自己的关卡。
2. 调整位置和体积，包住整张地面和三层空间，包括楼梯周围的活动区域。
3. 生成器的 Affect Navigation 和 Enable Collision 均开启。
4. 在关卡视口按 `P` 显示导航，检查可行走表面是否出现绿色区域，楼梯上下是否连起来。
5. 如楼梯断开，检查真实碰撞、坡度、步高以及导航 Agent 的半径/高度是否匹配角色，再调整导航生成参数。

这是 UE 的标准导航配置流程，见 [Epic 基础导航文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/basic-navigation-in-unreal-engine?application_version=5.6)。绿色覆盖仍需配合实际 AI 路径验收。

### 10.3 运行时改变地图

当前项目 `Config/DefaultEngine.ini` 已配置 Recast 的 `RuntimeGeneration=Dynamic`，但自己的关卡仍需要覆盖合适的 Nav Mesh Bounds Volume；关卡内已有 Recast Actor 的实例设置也要核对。

运行时生成新的地板表面应使用 Dynamic。Dynamic Modifiers Only 适合修改已有导航的代价/遮挡，不能代替新增表面的导航生成。生成完网格后，等导航可用再发 AI 移动请求，避免把“导航还没准备好”误判成寻路逻辑失败。参考 [Epic 导航更新模式](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-how-to-modify-the-navigation-mesh-in-unreal-engine?application_version=5.6)。

WFC 的 Walkable Components=1 只说明格子规则连通。它不会自动创建导航体积，也不会检查胶囊体能否穿过某个真实门洞。

## 十一、接入现有人物、敌人和传送

这一章是在自己的地图副本中继续开发的方向，当前插件尚未替你完成这部分业务接线。

### 11.1 使用现有初墨角色框架

现成 WFC 示例使用 GameModeBase，目的是独立查看布局。要测试现有角色，在自己的地图“世界设置 → GameMode Override”选择 **CC Adventure Game Mode**，并设置位于已确认地面上方的 Player Start。

该 C++ 游戏模式会使用原项目的角色、控制器、PlayerState 和 HUD。先使用编辑器已生成并保存的地图；运行时随机生成还要协调 Pawn 出生时机，防止角色先出生、地面后出现。

详细角色接入见[AdventureGameMode 配置](../../../Docs/CPPClasses/ACC_AdventureGameMode.md)。

### 11.2 将格子变成世界坐标

Cells 中的 Coordinate 是整数格子坐标。若需要在格子中心放置对象：

```text
LocalPosition = Coordinate × TileSet.CellSize
WorldPosition = 生成器的 Actor Transform.TransformLocation(LocalPosition)
```

这只是格子基准位置。出生点还要按模型的实际地板高度、角色胶囊高度加偏移，并通过向下射线、空间占用检查或导航投影确认落脚点。楼梯格不能直接当平地出生。

敌人生成建议筛选 Walkable=true 的普通地板，避开出生点和楼梯，等待导航准备后再生成/启动 AI。TileIndex 对应本次规则资产的 Tiles 数组；若修改了规则或数组顺序，应重新生成布局。

### 11.3 传送和存档

当前地区菜单只配置休憩之地、小镇、山河社稷。创建 WFC 地图不会自动添加第四个地区，也不会自动写入原角色进度。接入时需要另外登记地图路径、地区 ID、解锁条件以及出生位置。

如果随机种子需要跨启动保持，应扩展存档保存“规则版本 + TileSet 标识 + 设置 + 固定格 + 种子”，并在进入时恢复。原有地图框架说明见[地图传送与小地图配置](../../../Docs/地图传送与小地图配置.md)。

## 十二、保存、复现和打包

编辑器制作好地图后，保存自己的规则资产、蓝图和关卡。已生成的 HISM 实例及 Displayed Result 会随关卡保存，再次打开可以查看；不必每次 BeginPlay 都重新生成。

复现布局时，需要保持规则内容、Tiles/旋转顺序和生成参数一致。规则改变后，仅保留旧种子不能保证结果完全相同。保存调试截图时也建议记录 Requested Seed、Effective Seed、Attempts 和规则版本。

当前项目有显式 MapsToCook 清单，尚未包含新建的 WFC 地图。将来打包自己的随机场景时，在项目打包设置的地图列表加入自己的关卡，并确认 TileSet、网格、材质等依赖随包；不要只在字符串里拼资源路径而漏掉烹饪依赖。开源模型的许可通知也要随实际发布包保留。

## 十三、按症状排错

| 症状 | 优先检查 |
|---|---|
| 找不到插件地图 | 开启显示插件内容，确认插件启用，搜索完整资源名 |
| 没有 Generate Map 按钮 | 确认选中关卡中的生成器 Actor，而非规则资产或单块模型；编译并保存自己的生成器蓝图 |
| InvalidInput | TileSet 是否为空、ID 是否唯一、权重是否正数、旋转是否重复、固定格是否越界 |
| 缩小尺寸后突然失败 | 先处理 Pinned Cells，尤其原平面例子的 `(6,6,0)` |
| Contradiction | 边界名字是否可满足、相对接口是否匹配、固定朝向是否允许、楼层限制是否冲突 |
| Disconnected | 可走格是否被建筑隔开、Traversable Sockets 是否正确、跨层是否有 Stair |
| 改三层为一层失败 | 清除 BottomStair 固定格，增加/保留 SingleFloor |
| 换种子看起来相同 | 是否只有一种候选，或固定格/约束已经唯一确定；检查 Last Result 是否成功 |
| 新生成失败但旧图还在 | 这是失败保留旧图；对比 Last Result 和 Displayed Result |
| 模型整体悬空/埋地 | 检查网格 Pivot 和 Mesh Transform；不要照搬下载模型的 +90 cm |
| 拼接处有缝、重叠或门不对齐 | 检查实际尺寸、格子大小、朝向、模块局部偏移和接口填写 |
| 材质回退或用途警告 | 给材质开启 Used with Instanced Static Meshes，检查材质引用能否加载 |
| 模型有了但 AI 不走 | Nav Mesh Bounds Volume、组件导航开关、碰撞、动态重建状态、Agent 尺寸 |
| 格子连通但楼梯上不去 | 检查几何开口、碰撞、坡度、步高、平台高度和胶囊体净高 |
| 生成变慢或 BudgetExceeded | 先减少格数和变体，检查规则矛盾，再考虑增加有上限的预算 |
| 蓝图角色仍是自由相机/默认 Pawn | 自己的地图是否使用 CC Adventure Game Mode，Player Start 是否有效 |
| 打包后进不了新地图 | 检查地图是否列入 MapsToCook，相关资源是否随包 |

硬上限：每轴 1～64、总格子不超过 4096、立体 1～3 层、旋转变体不超过 256。`64×64×3` 超出总格数，不能使用。

## 十四、C++ 和素材工具入口

### C++ 最小接入

调用方 Build.cs 根据使用范围添加 Private 或 Public 依赖 `SpiritWFC`，再包含 `WFCSolver.h`：

```cpp
const FWFCGenerationResult Layout = FWFCSolver::Solve(TileSet, Settings);
if (Layout.Status == EWFCResultStatus::Success)
{
    // 使用 Layout.Cells，或让场景里的 AWFCMapGenerator 负责实例化。
}
else
{
    // 向设计界面报告 Layout.Message，不使用失败时的空 Cells。
}
```

只使用蓝图时，不需要修改原游戏模块的 Build.cs。

### 已提供的工具

| 项目根目录下的脚本 | 用途 |
|---|---|
| `Scripts/WFC/download_reference_models.py` | 按固定版本下载源 FBX、许可与哈希清单 |

完整命令见[开源模型来源与许可证](开源模型来源与许可证.md)。`-WFCRebuildSamples` 会显式重置样例规则/蓝图并重建自身示例对象，自定义内容应另存副本。普通使用无需重新下载或运行这些脚本。

## 十五、完成标准和阅读顺序

按以下顺序验收自己的第一套规则：

1. 4×4 平面成功，16 格，无缝、地面高度正确。
2. 两个相同接口的外观变体能随种子变化，相同种子可复现。
3. 道路出口吻合边界和邻格，固定格能出现在指定位置。
4. 4×4×3 生成 48 格，楼梯列对应，格子可通行分量为 1。
5. 手动检查角色穿门、走楼梯、落地；导航和 AI 路径通过。
6. 最后再接敌人出生、传送解锁、存档和打包。

参数不清楚时查[配置与接入](配置与接入.md)；想理解最小熵、加权选择、传播和整图重试时查[WFC 算法与贪心策略](WFC算法与贪心策略.md)；已验证范围见[验证记录](验证记录.md)。
