# 死亡布娃娃与经验粒子配置

当前测试入口保持 `/Game/HPWH/Maps/L_FlatTestArena`。玩家和敌人死亡后先进入 Death 动画，默认 0.65 秒后启用骨骼网格物理；敌人从死亡时起 10 秒后清理。低/中/高级/精英有效击杀分别奖励10/40/200/500经验，通过经验粒子实际领取，黑色经验包面向它按 E 产生 50 个。每颗接触领取者胶囊后消失，按ExperienceValue入账；1～128总额时每颗1，超过128总额均摊到最多128颗；产生时不会预先入账。

## 实际结算方式

```text
服务器判定敌人首次死亡 → 分级奖励的 ExperienceOrb → 物理散射 0.45 秒
                                        ↓
                                停止物理、加速吸向击杀者
                                        ↓
                       接触角色胶囊 → 该颗 +ExperienceValue 并销毁

E 瞄准黑色经验包 → 服务器校验距离/视线/未消费 → 同样流程，50 颗
```

每颗由 `CC_ExperienceOrb` 的 Sphere 碰撞负责服务器物理、移动和拾取，附着一个 Niagara Sprite 负责显示。Niagara 设为局部空间单颗粒子，所以散射和吸附轨迹始终跟随碰撞球，视觉数量与结算对象一致。客户端 Niagara 碰撞事件不直接增加经验；重复伤害、重复交互和同一颗重复接触都不会重复发奖。专用服务器保留物理与结算，跳过视觉组件激活。

掉落归属绑定 `CC_PlayerState`，不会附着到尸体，也不会因尸体 10 秒清理而连带销毁。领取者暂时死亡时停止追踪，仍保留最长 60 秒的粒子寿命；复活或换 Pawn 后继续寻找该 PlayerState 的当前活角色。当前未制作地面掉落存档或掉线托管，超时未领取的经验会消失。

## 布娃娃配置

在玩家或敌人派生蓝图的 Class Defaults → Crash → Death 配置：

| 字段 | 当前值 | 用途 |
|---|---|---|
| Enable Death Ragdoll | 开 | 死亡后是否启用布娃娃 |
| Death To Ragdoll Delay | 0.65 秒 | 给 Death 动画先倒地的时间，0 为立即进入物理 |
| Corpse Lifetime | 10 秒 | 仅敌人：从死亡开始计时清理；0 保留尸体 |

Mesh 必须有适合当前骨架和实际尺寸的 Physics Asset，活着时保持普通动画驱动，不要在蓝图 BeginPlay 另开 Simulate Physics。死亡路径会取消技能、停移动、禁用胶囊碰撞，再把 Mesh 交给 Ragdoll 碰撞与物理。当前导入模型具有特殊根骨骼尺度，替换 Physics Asset 时先单独检查体积、约束和落地表现。

蓝图可读取 `Is Ragdoll Active`。复活调用 `Reset Attributes` 恢复属性，再调用 `Handle Respawn`；后者清理死亡定时器，关闭物理，重新挂接 Mesh 并恢复碰撞、移动和形态外观。它不决定复活位置、无敌期或复活 UI；正式流程仍由游戏规则安排。`SetAlive` 只用于底层状态设置，不替代完整复活流程。

## 配怪物经验掉落

`CC_EnemyCharacter` 派生蓝图中：

- Experience Reward：有CombatBalance时由档案应用T1=10/T2=40/T3=200/Elite=500；-1继承父行，陶罐头200。没有共享档案的原型可直接填奖励。
- Experience Particle System：`/Game/HPWH/Effects/NS_ExperienceOrb`；留空使用同一路径的默认系统。
- 不在蓝图死亡事件里再调用 Add Experience，避免与逐颗拾取重复。

伤害源必须能解析到有效玩家的 PlayerState 才有领取者。环境伤害、没有玩家归属的死亡不会凭空给任意附近玩家发奖。同一轮死亡只创建一波；生命恢复为正后才允许下一轮死亡奖励。

## 配黑色经验包

关卡中的黑色方块使用 `/Game/HPWH/Blueprints/BP_ExperiencePack`，Mesh 使用方块和 `M_ExperiencePackBlack` 纯黑材质，带 `50 XP [E]` 文字。已放在出生点左前方，Actor 名 `Experience_Pack_Black_50XP`，位置约 `(-350, -350, 50)`。新增时复制现有经验包蓝图，拖到场景即可。

| 字段 | 默认值 | 用途 |
|---|---|---|
| Experience Amount | 50 | 一次发出 50 颗，每颗 1 经验 |
| Experience Particle System | NS_ExperienceOrb | 与怪物共享视觉系统 |
| Interaction Distance | 250 cm | 角色到碰撞包围盒最近表面的服务器最大交互距离 |
| Repeatable | 关 | 默认一次消费，成功后隐藏并关闭方块碰撞 |
| Reuse Delay | 1 秒 | 开启 Repeatable 时，两次成功领取间的最短间隔 |

面向黑色方块按 E，沿用控制器原有相机 Visibility 射线；服务器再次验证角色存活、距离、视线与消费状态。需要反复测试经验时可在专用测试实例开启 Repeatable，仍有间隔保护。方块消费状态只存在本局，不写本地或后端存档。

经验量在 1～128 时每颗为 1 经验；更大的单次量最多生成 128 个 Actor，并把总值均分到各颗，避免一次生成大量复制 Actor。当前 10/50 的要求始终保持一颗 1 经验。

## 改 Niagara 外观

`NS_ExperienceOrb` 是独立可编辑系统，不修改引擎自带模板。材质控制圆形/发光颜色，Sprite Renderer 和 Initialize Particle 控制尺寸。保持单颗、Local Space、无自身位移，移动由 ExperienceOrb 决定；不要额外增加 Spawn Rate 或 Niagara 速度，否则屏幕数量/位置会和拾取碰撞不一致。

`CC_ExperienceFXSetupLibrary.BuildExperienceOrbSystem` 供编辑器脚本重建这个基础系统。正式调整后先复制到自用目录并修改怪物/经验包引用，不要直接重跑生成脚本覆盖已经定制的系统。

上述资产与关卡引用已经保存，试玩不需要重新生成。维护脚本为 `Scripts/configure_experience_pickups.py`；它会重建同名经验材质/系统、更新经验包蓝图与当前平地场，所以正式手工定制后先复制资产并调整引用，避免覆盖修改。

需要重建时使用完整编辑器的 `-ExecutePythonScript`，并保留真实渲染后端：

```powershell

  'C:\Users\29717\Desktop\GASCrashCourse-main\GASCrashCourse-main\CrashCourse.uproject' `
  -unattended -RenderOffscreen `
  '-ExecutePythonScript=C:\Users\29717\Desktop\GASCrashCourse-main\GASCrashCourse-main\Scripts\configure_experience_pickups.py' -log
```

不要为该资源生成脚本使用 `-NullRHI` 或 `-run=pythonscript`。本机 UE 5.6 在 NullRHI 下由 ActorFactory 放置方块会触发零尺寸 HitProxy 缓冲错误；完整编辑器加 `-RenderOffscreen` 已实际生成并保存成功。它与下文只执行游戏逻辑的 smoke 不是同一运行模式。生成记录位于 `Saved/ExperiencePickupSetup.json`。

## 本轮验证结果（2026-10-23）

UE 5.6 `CrashCourseEditor / Win64 / Development` 编译成功。最终核心自动化报告 `Saved/Automation/ExperienceIntegrationFinal/index.json` 为 3/3 Success，0 警告、0 失败，覆盖成长交易与伤害、属性控件生命周期及巡逻状态切换。

- 重复致死仅生成 10 颗，经验包连续请求仅生成 50 颗；两种来源均不在产生时预入账。
