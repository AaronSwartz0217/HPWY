# 空场景 → 启动 → 玩法 → UI：源码消化笔记

> 只读梳理，未改任何代码。所有结论以当前源码为准，配置文档只作交叉验证。
> 阅读顺序建议：本文 → [从零配置与接入步骤](../从零配置与接入步骤.md) → [完整功能更新与配置说明](../完整功能更新与配置说明.md) → `Docs/CPPClasses/` 单类文档。

---

## 0. 一句话总览

这个项目不是「地图里摆好角色和 UI 然后 Play」的结构，而是：

**GameInstance 负责跨地图的会话与旅行 → GameMode 按地图名决定用哪套规则 → 引擎生成 PlayerState / Controller / Pawn / HUD → Pawn 被 Possess 时初始化 GAS → 控制器和 HUD 自己 CreateWidget 把 UI 挂到 Viewport。**

地图里摆的 Actor 主要提供「内容」（传送门、商店、经验包、刷怪器、地形块），**玩法的骨架（GAS、成长、UI、存档）全是 C++ 类在运行时自举出来的**。

## 1. 先分清三种「空场景」

| 场景类型 | 判定方式 | GameMode | 自动生成什么 | 结果 |
|---|---|---|---|---|
| 主菜单地图 `L_MainMenu` | 文件名等于 `GameInstance.MainMenuMap` 的资源名 | `ACC_MainMenuGameMode` | Controller + 菜单 UI，**没有 Pawn** | 一个纯 UI 的空场景，这是设计意图 |
| 四个地区地图（Rest/Town/Arena/Heaven） | 文件名等于 `Regions[*].Map` 的资源名（允许 `_名字` 后缀） | `ACC_AdventureGameMode` | PS/PC/Pawn/HUD 全套（需要 PlayerStart） | 完整玩法 |
| 其它任意地图（包括复制出来的空图） | 不匹配上面两条 | `GlobalDefaultGameMode` = `GameModeBase` | 默认 `ADefaultPawn`，无自定义 HUD/UI | **不接 GAS、不接 UI** |

判定逻辑在 [CC_AdventureGameInstance.cpp:98-113](../../Source/CrashCourse/Private/World/CC_AdventureGameInstance.cpp#L98-L113)：

- `RegionForMap()` 只比较**资源短名**，不读 World Settings。
- `OverrideGameModeClass()` 对主菜单返回 `ACC_MainMenuGameMode`，对地区返回 `ACC_AdventureGameMode`，其它交给父类。
- 因此**关卡 World Settings 里的 GameMode Override 会被直接覆盖**，这一点在 [从零配置与接入步骤.md:9](../从零配置与接入步骤.md) 也有说明。

> 坑：把 `restartlife` 复制成 `MyTestMap` 再打开，它不会进 AdventureGameMode，而是一个只有 DefaultPawn 的空场景。要么改名成 `restartlife_xxx`（后缀匹配），要么在 World Settings 里手动指定 `BP_ProgressionGameMode`。

### 1.1 「地区地图 + 没有 PlayerStart」会发生什么

这是「进入没有物体的空界面」最接近的情况。游戏流程是：

1. GameMode 构造时设置 `DefaultPawnClass / PlayerControllerClass / PlayerStateClass / HUDClass`（[CC_AdventureGameMode.cpp:20-30](../../Source/CrashCourse/Private/World/CC_AdventureGameMode.cpp#L20-L30)）。
2. 引擎走 `PostLogin → HandleStartingNewPlayer → RestartPlayer`，`RestartPlayer` 依赖 `ChoosePlayerStart` 找到 PlayerStart。
3. 项目里**没有任何自定义 PlayerStart 兜底**（全仓只有 `CC_AmbientSpawnDirector` 读取 PlayerStart 位置，见 [CC_AmbientSpawnDirector.cpp:30](../../Source/CrashCourse/Private/World/CC_AmbientSpawnDirector.cpp#L30)）。
4. `StartPlay` 里还有一次补生成：如果 PC 的 Pawn 不是 `ACC_PlayerCharacter`，就 `UnPossess + RestartPlayer`（[CC_AdventureGameMode.cpp:43-48](../../Source/CrashCourse/Private/World/CC_AdventureGameMode.cpp#L43-L48)）。没有 PlayerStart 时这次也会失败。

结果：

| 系统 | 是否还在 | 说明 |
|---|---|---|
| PlayerController | 在 | 输入、扫描组件、小地图、导航 UI 都会创建 |
| PlayerState + ASC + AttributeSet | 在 | 但 `InitAbilityActorInfo` 没被调用 |
| Pawn / Character | **没有** | 因此没有技能、没有属性初始化、没有角色血条 |
| HUD（`BP_MuralHUD`） | 在 | `PlayerHealthHUD` + `FirstPersonScanHUD` 会挂上，但显示 `— / —` |
| 世界导航 / 小地图 | 在 | 只要地区名匹配且是本地控制器就会创建 |
| 存档 | 不会自动写 | `RestoreSessionProgress` 需要 Progression 与 Pawn，没 Pawn 就到不了这一步 |

因此「空场景里能看到 UI」是正常的：**UI 由 Controller/HUD 自举，不依赖地图里摆 Actor**；但「没有角色」意味着 GAS 整条链停在 `Possess` 之前。

## 2. 启动时序（从双击 Play 到能放技能）

### 2.1 引擎启动 / GameInstance 阶段

1. 引擎创建 `UCC_AdventureGameInstance`（`Config/DefaultEngine.ini:7` 指定）。
2. `Init()`：
   - 读 `SpiritTales` 存档 → `SessionProgress`（版本 1–4 才接受，否则置 `bRestoreFailed`）。
   - 注册 `PreLoadMapWithContext`（加载屏）与 `OnTravelFailure`。
   - 见 [CC_AdventureGameInstance.cpp:50-67](../../Source/CrashCourse/Private/World/CC_AdventureGameInstance.cpp#L50-L67)。
3. 构造函数里已经写好了**旅行地区注册表**（Rest / Town / Arena / Heaven）与主菜单、LOGO、背景乐路径（[CC_AdventureGameInstance.cpp:35-49](../../Source/CrashCourse/Private/World/CC_AdventureGameInstance.cpp#L35-L49)）。

### 2.2 主菜单

4. 加载 `L_MainMenu`（`Config/DefaultEngine.ini:4`）。
5. `CC_AdventureGameInstance::OverrideGameModeClass` → `ACC_MainMenuGameMode`。
6. `ACC_MainMenuGameMode` 构造：`DefaultPawnClass=nullptr`、`HUDClass=AHUD`、`PlayerControllerClass=ACC_MainMenuController`；`RestartPlayer` 被重写成空实现（[CC_MainMenuGameMode.cpp:5-12](../../Source/CrashCourse/Private/World/CC_MainMenuGameMode.cpp#L5-L12)）。
7. `ACC_MainMenuController::BeginPlay`：
   - `CreateWidget<UCC_MainMenuWidget>(MainMenuClass 或原生类)`
   - `AddToViewport(100)`、显示鼠标、`FInputModeUIOnly`
   - 通知 GameInstance 播放背景乐
   - 见 [CC_MainMenuController.cpp:5-13](../../Source/CrashCourse/Private/Player/CC_MainMenuController.cpp#L5-L13)。
8. `UCC_MainMenuWidget` 在 `RebuildWidget()` 里**用 C++ 构建整页布局**（背景、LOGO、三个按钮、Loading 面板、开场 LOGO 遮罩），美术读 `DA_HomeArt`（`UCC_MenuArtData`），见 [CC_MainMenuWidget.cpp:26-74](../../Source/CrashCourse/Private/UI/CC_MainMenuWidget.cpp#L26-L74)。开场 LOGO 只播一次，由 GameInstance 的 `ConsumeStartupLogo()` 控制。

### 2.3 点「开始游戏」

9. `StartGame()` → `UCC_AdventureGameInstance::StartGameFromHome()`：
   - 校验主菜单世界、单机、非旅行中；
   - 没有存档就新建一份 `NativeFormId=InitialInk` 的快照；有存档就反序列化并按版本校验；
   - 备份当前会话 → `AdoptProgressSnapshot` → `StartPackageLoad("Rest", 地图包)`。
   - 见 [CC_AdventureGameInstance.cpp:127-144](../../Source/CrashCourse/Private/World/CC_AdventureGameInstance.cpp#L127-L144)。
10. `StartPackageLoad` 起一个 50ms 的 Ticker + `LoadPackageAsync`，加载屏进度写在 `FCC_LoadingPresentation` 原子变量里；加载完在下一帧 `OpenLevel`（[CC_AdventureGameInstance.cpp:316-347](../../Source/CrashCourse/Private/World/CC_AdventureGameInstance.cpp#L316-L347)）。
11. 真正切图前，`PreLoadMapWithContext` 会调 `PrepareLoadingScreen`，把 `SCC_LoadingScreen`（Slate 自绘）交给 MoviePlayer（[CC_AdventureGameInstance.cpp:348-366](../../Source/CrashCourse/Private/World/CC_AdventureGameInstance.cpp#L348-L366)）。

### 2.4 进入地区地图

12. 旧世界销毁 → 新世界加载 → `ACC_AdventureGameMode`：
    - `InitGame`：扫描地图里的 Pawn，把「非 `ACC_PlayerCharacter` 且 AutoPossessPlayer 打开」的旧模板角色隐藏、禁碰撞、禁 Tick，打 `CC_LegacyPlayer` 标签（[CC_AdventureGameMode.cpp:31-37](../../Source/CrashCourse/Private/World/CC_AdventureGameMode.cpp#L31-L37)）。
    - `StartPlay`：`ConfigureLegacyActors()`（把旧 `BP_传送门判断` 换成 `ACC_MapPortal`；Town 里则隐藏旧传送门）；再补一次 `RestartPlayer`；然后 `HandleRegionEntered`；Town/Arena 若没有 `ACC_CoinSpawnDirector` 就 Spawn 一个（[CC_AdventureGameMode.cpp:38-59](../../Source/CrashCourse/Private/World/CC_AdventureGameMode.cpp#L38-L59)）。
13. 引擎按 GameMode 配置生成：
    - `BP_ProgressionPlayerState`（父类 `ACC_PlayerState`）→ 构造时创建 `Progression`、`AbilitySystemComponent`、`AttributeSet`（[CC_PlayerState.cpp:9-19](../../Source/CrashCourse/Private/Player/CC_PlayerState.cpp#L9-L19)）
    - `BP_ProgressionController`（父类 `ACC_PlayerController`）→ 构造时创建 `Scanner` 组件
    - `BP_ProgressionCharacter`（父类 `ACC_PlayerCharacter`）
    - `BP_MuralHUD`（父类 `ACC_ProgressionHUD`）
14. **Pawn 被 Possess 是 GAS 的总开关**（[CC_PlayerCharacter.cpp:147-163](../../Source/CrashCourse/Private/Characters/CC_PlayerCharacter.cpp#L147-L163)）：
    1. 从 PlayerState 取 ASC；
    2. `InitAbilityActorInfo(PlayerState, this)`；
    3. 广播 `OnASCInitialized`（世界血条 `UCC_WidgetComponent` 靠它绑定）；
    4. `GiveStartupAbilities()`（每个 Avatar 只发一次）；
    5. `InitializeAttributes()`（应用默认初始化 GE）；
    6. `Progression->InitializeAvatar()`；
    7. 订阅 `Health` 变化 → `OnHealthChanged` → 死亡判定。
15. `Progression::InitializeAvatar()`（[CC_ProgressionComponent.cpp:69-98](../../Source/CrashCourse/Private/Progression/CC_ProgressionComponent.cpp#L69-L98)）：
    - 第一次绑定时缓存人形 Mesh / 缩放 / AnimClass 与初始属性；
    - 服务器端 `ApplyState(true)`：解析形态三档 → 合并购买加成 → 写 ASC 基础属性 → 换 Mesh/Anim → `Skills->ApplyLoadout()`；
    - 然后 `Adventure->RestoreSessionProgress(this)`，成功且世界已 BeginPlay 时再触发一次 `HandleRegionEntered`。
16. `HandleRegionEntered`（[CC_AdventureGameInstance.cpp:182-206](../../Source/CrashCourse/Private/World/CC_AdventureGameInstance.cpp#L182-L206)）：
    - 播放/恢复背景乐；
    - 记录 `CurrentRegion`、把该地区加入 `VisitedRegions`；
    - 恢复进度快照；
    - 消耗传送卷轴（如果是卷轴旅行）；
    - 保存进度（`SaveCurrentProgress`）；
    - 清理旅行状态与加载屏。
17. 同时，Controller / HUD 的 `BeginPlay` 把 UI 挂上：
    - HUD：`PlayerHealthHUD`（z=5）、`FirstPersonScanHUD`（z=6）（[CC_ProgressionHUD.cpp:22-27](../../Source/CrashCourse/Private/Progression/CC_ProgressionHUD.cpp#L22-L27)）
    - Controller：`ACC_MinimapCapture` + `UCC_WorldNavigationWidget`（z=90）（[CC_PlayerController.cpp:38-49](../../Source/CrashCourse/Private/Player/CC_PlayerController.cpp#L38-L49)）

### 2.5 旅行 / 死亡重生

- **传送门**：`ACC_MapPortal` 重叠 → `ArmPortalDeparture`（30 秒冷却、登记 ActiveDeparture）→ 播 8 秒 Niagara → `RequestPortalTravel` → `BeginTravel`（[CC_MapPortal.cpp:35-82](../../Source/CrashCourse/Private/World/CC_MapPortal.cpp#L35-L82)）。
- **快速旅行**：在角色面前 Spawn 一个临时传送球（`bTemporaryPortal=true`），同样走 `ArmPortalDeparture → BeginTravel`。
- `BeginTravel` 的顺序很重要：**先校验 → 先存档 → 再关菜单/停移动/暂停世界 → 异步加载**（[CC_AdventureGameInstance.cpp:303-315](../../Source/CrashCourse/Private/World/CC_AdventureGameInstance.cpp#L303-L315)）。存档失败就不会开始传送。
- **死亡**：`ACC_PlayerCharacter::HandleDeath` 清消耗品效果、取消输入 → `ACC_BaseCharacter` 进入死亡表现（0.65 秒后布娃娃，敌人 10 秒后 `Destroy`）→ 5 秒后 `GameInstance::RespawnAtRest` → `BeginTravel("Rest", 允许锁定, 重生模式)`（[CC_PlayerCharacter.cpp:182-193](../../Source/CrashCourse/Private/Characters/CC_PlayerCharacter.cpp#L182-L193)、[CC_BaseCharacter.cpp:87-140](../../Source/CrashCourse/Private/Characters/CC_BaseCharacter.cpp#L87-L140)）。

## 3. 类职责总表：谁创建谁、读什么、写什么、删什么

### 3.1 流程层

| 类 | 谁创建 / 何时 | 读什么 | 持有 / 写什么 | 创建什么 | 销毁什么 |
|---|---|---|---|---|---|
| `UCC_AdventureGameInstance` | 引擎；进程启动 | Config 地区表、`SpiritTales` 存档 | `SessionProgress`、`VisitedRegions`、`CurrentRegion`、`bTravelling`、加载原子量 | 加载屏、背景乐组件、临时传送球、异步加载 Ticker | 音乐组件（Shutdown）、加载 Ticker、传送球（`bTemporaryPortal`） |

| `ACC_AdventureGameMode` | 引擎；地区图 | 地图里的旧 Pawn / 旧传送门、GameInstance 地区名 | 类默认值 | `ACC_CoinSpawnDirector`（Town/Arena）、`ACC_MapPortal`（替换旧门） | 隐藏/禁用旧 Pawn；Town 里隐藏旧传送门 |

| `UCC_ProgressionComponent` | PlayerState 构造 | Form/Upgrade/Skill DataAsset、ASC 当前属性、存档 | 经验、铜币、三档形态、购买等级、手动技能、道具、当前商店 | 存档对象 `UCC_ProgressionSave`、运行时 Loadout 校验对象 | `ClearConsumableEffects`、清空道具/表单（读档、开发者预设） |
| `UCC_ProgressionSave` | Progression / GameInstance | 当前 Progression + GameInstance 访问记录 | 版本、经验、形态档位、升级、技能 ID、道具、地区 | 无 | 被新快照覆盖 |

## 4. UI 是怎么「进到场景」的

### 4.1 三条注入路径

| 路径 | 机制 | 用在哪 |
|---|---|---|
| **A. C++ `CreateWidget` + `AddToViewport`** | 控制器/HUD 在 `BeginPlay` 里自建，带 ZOrder | 主菜单、血条/战技面板、扫描 HUD、世界导航、Tab 菜单 |
| **B. Actor 的 `WidgetComponent`（世界空间）** | Actor 构造时挂组件，Slate 画在 3D 位置上 | 角色头顶血条 `HealthDisplay`、小镇商店招牌 `UCC_TownShopSign` |
| **C. UMG 内部再嵌 Widget** | 父 Widget 在 `NativeOnInitialized` / `RebuildWidget` 里创建子 Widget | `WBP_MuralMenu` 内建 `OptionsPanel`、`SkillGalleryWidget`；主菜单内建 Loading 面板 |

### 4.2 界面清单

| 界面 | 创建者 | 时机 | 挂载点 | 数据来源 | 关闭 / 销毁 |
|---|---|---|---|---|---|
| `UCC_MainMenuWidget` | `ACC_MainMenuController` | 主菜单 BeginPlay | Viewport z=100，UIOnly | `DA_HomeArt`、GameInstance 旅行状态/错误 | Controller `EndPlay` → `RemoveFromParent` |
| `UCC_PlayerHealthHUDWidget` | `ACC_ProgressionHUD` | 游玩关 BeginPlay | Viewport z=5 | ASC 的 Health/MaxHealth 委托、`Progression.OnChanged`、Skills 槽位与冷却、道具槽 | HUD `EndPlay` → 移除 |
| `UCC_FirstPersonScanWidget` | `ACC_ProgressionHUD` | 游玩关 BeginPlay | Viewport z=6 | `PC->Scanner`、`FindInteractionTarget`、`DA_ScanCatalog` / `UCC_ScanTargetComponent` | HUD `EndPlay` → 移除 |
| `UCC_WorldNavigationWidget` | `ACC_PlayerController` | BeginPlay（地区名匹配时） | Viewport z=90 | `ACC_MinimapCapture`、GameInstance 地区解锁状态 | Controller `EndPlay` → 移除 |
| `UCC_ProgressionMenu`（原生回退） | `ACC_PlayerController` | 按 Tab | Viewport z=100，GameAndUI | Progression 目录、Skills 槽位、Controller 组合键 | 再按 Tab / 关闭 → `RemoveFromParent` |
| `WBP_MuralMenu`（父类 `UCC_MuralMenuWidget`） | `ACC_PlayerController`（`ProgressionMenuClass` 指向它） | 按 Tab / 商店请求 | Viewport z=100 | Progression + Skills + `DA_MenuArt`；内建 `UCC_OptionsWidget`、`UCC_SkillGalleryWidget` | 关闭时移除 |
| `SCC_LoadingScreen`（Slate） | `UCC_AdventureGameInstance` | 切图前 / 主菜单 Loading 面板 | MoviePlayer 或主菜单内嵌 | `LoadingPresentation` 原子量、LOGO、地区名 | 加载结束自动消失 |
| `UCC_TownShopSign` | `ACC_TownShop`（世界 Actor） | 商店 BeginPlay | 世界空间 WidgetComponent | `ShopId` | 随 Actor 销毁 |
| `UCC_AttributeWidget`（头顶血条） | `ACC_BaseCharacter::HealthDisplay` | 角色构造 | 世界空间 WidgetComponent | `UCC_WidgetComponent` 订阅 ASC 属性 | 玩家 HUD 绑定后主动隐藏世界血条 |

### 4.3 输入模式切换（容易踩的点）

- 主菜单：`FInputModeUIOnly`，聚焦主菜单（[CC_MainMenuController.cpp:12](../../Source/CrashCourse/Private/Player/CC_MainMenuController.cpp#L12)）。
- Tab 菜单：`FInputModeGameAndUI` + `SetIgnoreMoveInput/LookInput(true)` + 鼠标可见；关闭时恢复 `GameOnly`（[CC_PlayerController.cpp:400-433](../../Source/CrashCourse/Private/Player/CC_PlayerController.cpp#L400-L433)）。
- 旅行菜单：同样 `GameAndUI`，但 `SetTravelMenuOpen(false)` 会检查 `IsProgressionMenuOpen()` 再决定是否回 `GameOnly`。
- 所有「玩法输入」入口都先过 `IsGameplayInputBlocked()`：菜单开、旅行锁、GameInstance `bTravelling` 三者任一为真就直接返回。

## 5. 一次技能释放的完整链路

### 5.1 输入 → 能力

1. `SetupInputComponent` 绑定 6 个组合键（1/2/3/4/J/E），并删除 EnhancedInput 里同名战斗映射，避免双触发（[CC_PlayerController.cpp:95-186](../../Source/CrashCourse/Private/Player/CC_PlayerController.cpp#L95-L186)）。
2. 按键 → `Primary()/Secondary()/...`：
   - 有 `CurrentLoadout` → `Skills->ActivateSlot(0..3)`
   - 没有 → 退回 `ASC->TryActivateAbilitiesByTag(CCTags::CCAbilities::Primary...)`
   - 见 [CC_PlayerController.cpp:263-291](../../Source/CrashCourse/Private/Player/CC_PlayerController.cpp#L263-L291)。
3. `SkillComponent` 在服务器上走 `TrySkillInput`（含 0.18 秒输入缓冲、队列、阻塞动作检查），非服务器则发 `ServerActivateSlot` RPC（[CC_SkillComponent.cpp:121-141](../../Source/CrashCourse/Private/Progression/CC_SkillComponent.cpp#L121-L141)）。
4. 真正激活由 ASC 执行，Ability 的 `SourceObject` 就是 `UCC_SkillDefinition`。

### 5.2 能力内部

`UCC_ConfiguredAbility` 是**唯一执行实现**，20 多个技能靠 DataAsset 配置：

1. `CanActivateAbility`：检查解锁、存活、眩晕、阻塞动作、冷却 Tag、法力（[CC_ConfiguredAbility.cpp:114-122](../../Source/CrashCourse/Private/Progression/CC_ConfiguredAbility.cpp#L114-L122)）。
2. `ActivateAbility`：记录本次 Attack 快照 → `CalculatePower` → 扣蓝（`ManaEffect` 负值）→ 启动冷却 → 瞄准 → 播放表现 → 有 Windup 就等延迟，否则直接执行（[CC_ConfiguredAbility.cpp:123-149](../../Source/CrashCourse/Private/Progression/CC_ConfiguredAbility.cpp#L123-L149)）。
3. `ExecuteSkill` 按 `Behavior` 分支：
   - 投射物类 → `SpawnProjectiles()`（散射按 `Count` 生成多个 `ACC_SkillProjectile`）
   - 位移 → 直接 `SetActorLocation`
   - 近战/连击/范围 → `Pulse()`，可多次脉冲
   - 治疗/护盾/增益 → 对自己 `ApplyEffect`
4. `ApplyEffect()` 是统一的 GE 派发口（[CC_ConfiguredAbility.cpp:80-113](../../Source/CrashCourse/Private/Progression/CC_ConfiguredAbility.cpp#L80-L113)）：构造 Spec、写入 `CCTags.Skill.Value` / `Duration`、可选打 `IndirectDamage`、可选给减速加 `Debuff.Slow`，然后 `ApplyGameplayEffectSpecToTarget`。

### 5.3 伤害 → 死亡 → 奖励

`UCC_AttributeSet::PostGameplayEffectExecute`（[CC_AttributeSet.cpp:34-89](../../Source/CrashCourse/Private/AbilitySystem/CC_AttributeSet.cpp#L34-L89)）：

1. 只处理 `IncomingDamage` meta 属性；
2. 防御减伤公式：`Damage * 100 / (100 + Defense)`；
3. 护盾先吸收，再扣 Health 并 clamp；
4. 通知攻击方 `Skills->OnDamageDealt`（吸血、状态机等）；
5. 敌人死亡（`Health<=0 && !bDeathRewarded`）：
   - `ACC_ExperienceOrb::SpawnBurst` 生成经验球（数量和单颗数值由敌人与上限分摊）
   - `Progression->AddCopperCoins(CopperReward)`
   - 发 `CCTags.Events.KillScored` 事件
6. `PostAttributeChange` 里：回血会重置 `bDeathRewarded`；`MoveSpeed` 变化直接写 `MaxWalkSpeed`（所以减速/加速 GE 立刻生效）。

### 5.4 UI 刷新

- 血条：订阅 ASC 的 Health/MaxHealth 委托 → 立即刷新（[CC_PlayerHealthHUDWidget.cpp:92-102](../../Source/CrashCourse/Private/UI/CC_PlayerHealthHUDWidget.cpp#L92-L102)）。
- 经验/铜币：订阅 `Progression.OnChanged` → `RefreshProgression`，同时更新 Rainbow 血条材质（[CC_PlayerHealthHUDWidget.cpp:263-297](../../Source/CrashCourse/Private/UI/CC_PlayerHealthHUDWidget.cpp#L263-L297)）。
- 技能冷却：`GetCooldownRemaining` 每次查询 ASC 上带冷却 Tag 的 GE 剩余时间，不存 timer 字段（[CC_SkillComponent.cpp:157-166](../../Source/CrashCourse/Private/Progression/CC_SkillComponent.cpp#L157-L166)）。
- 战技面板 0.05 秒刷新一次，打开时只读，不改玩法状态。

## 6. 数据所有权：谁是真源

```
DataAsset(形态/技能/升级/平衡)
        │ 读
        ▼
UCC_ProgressionComponent (PlayerState) ──写─► ASC 基础属性 / Mesh / Anim / Loadout
        │ 广播 OnChanged                     │
        ▼                                    ▼
菜单 / HUD / 世界血条                  UCC_AttributeSet（GAS 真值）
        ▲                                    │ 委托
        └────────────── UI 只读 ◄────────────┘

GameInstance（SessionProgress / VisitedRegions）
        │ 只在 StartGame / BeginTravel / HandleRegionEntered 写盘
        ▼
UCC_ProgressionSave（Slot "SpiritTales"）
```

几条硬规则：

1. **玩家 ASC 在 PlayerState，不在 Pawn**。换 Pawn 或换 GameMode 但没换 PlayerState 子类，GAS 直接失效。
2. `ACC_BaseCharacter::GetAbilitySystemComponent()` 返回 `nullptr`，只有 `ACC_PlayerCharacter`（转发到 PlayerState）和 `ACC_EnemyCharacter`（自己的 ASC）重写（[CC_BaseCharacter.cpp:53-56](../../Source/CrashCourse/Private/Characters/CC_BaseCharacter.cpp#L53-L56)）。
3. 存档只由 `UCC_ProgressionComponent::SaveProgress` 和 GameInstance 的旅行流程触发；`SaveCurrentProgress` 还要求 `RestoredProgression == 当前 Progression`，防止「还没读档就写档」把存档冲掉（[CC_AdventureGameInstance.cpp:170-181](../../Source/CrashCourse/Private/World/CC_AdventureGameInstance.cpp#L170-L181)）。
4. 开发者会话 `MarkDeveloperSession()` 会打开 `bSuppressAutomaticSaves`，此时只更新内存快照，不写盘。

## 7. GameplayEffect / Tag 清单

| 类型 | 类 | 作用 | 关键点 |
|---|---|---|---|
| 初始化 | `UCC_InitialAttributesEffect` | Override 8 项基础属性（100/100/100/100/15/0/0/500） | 与 BP 里的初始化 GE 二选一 |
| 伤害 | `UCC_DamageEffect` | Instant，加 `IncomingDamage` | 值走 `CCTags.Skill.Value` |
| 治疗 | `UCC_HealthEffect` | Instant，加 Health | — |
| 法力 | `UCC_ManaEffect` | Instant，加 Mana（技能扣蓝用负值） | — |
| 护盾 | `UCC_ShieldEffect` | Override Shield | 同时起一个到期清零的 Timer，用 `ShieldGeneration` 防串 |
| 防御/攻击/移速 | `UCC_DefenseEffect` / `UCC_AttackEffect` / `UCC_SpeedEffect` | HasDuration，SetByCaller 时长 | 移速会直接改 `MaxWalkSpeed` |
| 冷却 | `UCC_CooldownEffect` | HasDuration，无属性修改 | 动态授予 `CCTags.Cooldown.Slot1~4 / BasicAttack` |
| 冲刺 | `UCC_SprintEffect` | SetByCaller 倍率 | 玩家控制器管输入，角色管 GE |

Tag：

| Tag | 用途 |
|---|---|
| `CCTags.CCAbilities.Primary/Secondary/Tertiary` | 无 Loadout 时的旧式按 Tag 激活 |

| `CCTags.Skill.Value / Duration` | GE 的 SetByCaller |
| `CCTags.Skill.IndirectDamage` | 标记非直接伤害（影响吸血/受击统计） |

| `CCTags.Events.KillScored` | 击杀事件（GE 执行后发） |
| `CCTags.Events.Enemy.EndAttack` | 敌人技能结束，下一帧派发 |

## 8. 空场景 / 缺资源时的故障对照表

| 缺失项 | 现象 | 根因 |
|---|---|---|
| 地图不在 `Regions` 表 | 只有 DefaultPawn、没有 HUD/UI/GAS | `OverrideGameModeClass` 没匹配到，落回 `GameModeBase` |
| 地区图没有 PlayerStart | 有 Controller/HUD/导航，但**没有角色**，血条显示 `— / —` | 项目没有 `ChoosePlayerStart` 兜底，`RestartPlayer` 失败 |
| 地图里有旧模板 Pawn 且 AutoPossess | 玩家可能被旧角色抢走 | `InitGame` 会禁用，但 StartPlay 还会再检查一次；新图里不要摆 AutoPossess 角色 |
| `BP_ProgressionCharacter` 等蓝图被删 | 回退到 C++ 父类，能跑但没美术配置 | GameMode 构造里的 `FClassFinder` 有 fallback |
| `BP_MuralHUD` 缺失 | 回退 C++ HUD：调试面板打开、无拾取提示图 | `HUDClass` fallback 到 `ACC_ProgressionHUD` |
| `WBP_MuralMenu` 缺失 | Tab 打开原生文字菜单 | Controller 的 `ProgressionMenuClass` 为空时用 `UCC_ProgressionMenu` |
| Form 的 Stages 未填完整 | `ApplyState` 返回 false，属性/技能不更新 | `IsComplete()` 校验 |
| 存档版本 >4 或损坏 | 菜单提示「存档无法读取」，自动保存停用 | `bRestoreFailed` + `RestoreSessionProgress` 拒绝 |
| 场景里没摆 `ACC_AmbientSpawnDirector` | 没有敌人 | 刷怪器不是 GameMode 自动创建的；只有金币导演会自动补 |
| 场景里没摆 `ACC_TownShop` | 无法进店 | 商店是地图内容，不是 UI 自动生成 |
