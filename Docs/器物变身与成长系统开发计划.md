# 器物变身、经验货币、进化与四技能系统开发计划

日期：2026-10-23
工程：CrashCourse / Unreal Engine 5.6 / Gameplay Ability System
状态：规划基线；已开始实现逻辑原型。实际接口、资源路径与当前限制以《器物与技能配置指南》为准。

## 1. 已确认需求

- 玩家与怪物均使用四个技能槽。
- 先建设包含 20 个技能模板的技能库，名称和最终参数由用户后续配置。
- 玩家与场景中的特殊器物交互，获得对应变身形态。
- 特殊器物共四种，对应四种器物形态；另外有始终可用的原生形态。不选择器物时，也可以购买原生形态的三档进化。
- 变身后替换技能组，并改变角色数值。
- 每个形态分为初级、中级、高级三档，消耗经验完成进化。
- 经验类似货币：击杀获得、全形态共用，可购买进化、等级及属性加成。
- 切换形态后保留各形态进化等级。

## 2. 第一版规则与边界

以下为建议默认规则，实施时做成可配置项，避免写死在逻辑中。

1. 首次交互解锁形态并变身；再次交互使用已经购买的进化档位，不降级、不重复收费。
2. 初级通过交互免费获得；初级到中级、中级到高级分别购买，不能跳档，高级封顶。
3. 已解锁形态支持主动切换，也支持恢复原生形态；原生形态和四种器物形态分别记录进化档位。变身不替换 PlayerState，不清空经验。
4. 初版属性商品为全局永久加成，对人形和全部变身形态生效。形态专属商品作为后续扩展。
5. 形态进化档位、可购买的技能等级、可购买的属性等级分别记录，避免一个等级承担多种含义。
6. 切换形态或进化时保持当前生命与法力百分比；不能通过反复切换免费回血回蓝。死亡状态不能交互、变身或购买。
7. 技能切换保留共享冷却约束，不能通过变身清除冷却。持续施法、位移等旧技能按切换规则结束并清理。
8. 经验为非负整数。商品价格、等级上限、奖励数量均来自配置。经验余额不足时整笔交易失败。
9. 玩家与怪物共享四槽及技能库，怪物由 AI 触发技能，不使用玩家按键。
10. 初版不添加自动变身、付费解锁形态、消耗器物、死亡扣经验等未要求的规则。

## 4. 数据驱动设计

### 4.1 技能定义 SkillDefinition

每个技能使用稳定 ID（Skill_01 至 Skill_20），显示名称可随时更改，存档与引用不依赖名称。

建议配置：

- 技能 ID、显示名称、描述、图标。
- GameplayAbility 类、技能行为模板、允许使用者类型。
- 技能等级参数：伤害、法力消耗、冷却、距离、半径、持续时间等。
- 动画蒙太奇、命中通知、投射物类、Niagara、音效。
- 目标筛选：自身、友方、敌方；阵营与存活状态过滤。
- 前置状态、禁止状态、打断规则、位移规则、冷却组。
- AI 使用参数：最小／最大距离、优先级、权重、目标条件。

技能数据与槽位解耦：同一个技能可以被不同形态或怪物装备到不同槽位。

### 4.2 四槽技能组 AbilityLoadout

统一槽位为 Slot1、Slot2、Slot3、Slot4。现有 Primary／Secondary／Tertiary 映射至前三槽，增加第四槽；保留兼容路径，逐步迁移旧蓝图标签。

每槽记录技能定义、初始等级与可选等级覆盖。每组必须有四个有效技能；配置不完整时在编辑器校验并给出明确提示，运行时安全拒绝无效槽位。

切换技能组只撤销该组授予的能力，不删除死亡、受击、被动等公共能力。记录授予句柄，处理同技能复用、重生与重复初始化，避免能力越切越多。

### 4.3 形态定义 FormDefinition

- 稳定形态 ID、名称、图标、介绍。
- 初级、中级、高级三个阶段，每阶段独立配置。
- 各阶段：进入费用、四技能组、基础属性、移动速度、模型、动画蓝图及表现资源。
- 模型需明确骨架和动画兼容要求；必要时配置网格相对变换、胶囊体尺寸。
- 没有配置替换外观时保留当前兼容外观，并提示资源待补，不影响逻辑验证。

### 4.4 经验钱包与升级商品

钱包保存可用经验，可另外记录累计获得经验。消费只减少余额，不能把累计获得量当成可消费余额。

商品采用独立 UpgradeDefinition，包含：稳定 ID、类型、目标、等级价格表、最高等级、前置条件、每级收益。

| 商品类型 | 示例作用 | 记录方式 |
|---|---|---|
| 形态进化 | 指定形态初级到中级、中级到高级 | 每个形态独立档位 |
| 技能等级 | 提高指定技能的伤害或效果等级 | 按稳定技能 ID 记录购买等级 |
| 属性等级 | 最大生命、最大法力、攻击、防御、移速 | 按稳定商品 ID 记录购买等级 |

技能购买等级默认跨形态保留；怪物技能等级由自身配置。最终技能有效等级由技能组基础等级加已购买等级计算，并受配置上限限制。

价格使用明确的逐级列表，方便策划调整。第一版不固定经济数值，测试费用与奖励仅用于验证，不代表最终平衡。

下表是行为模板及临时编号，不是最终技能名称。每项都需要可运行的 GA 逻辑和配置数据，不以创建 20 个空类作为完成标准。

| ID | 行为模板 | 主要可配置参数 |
|---|---|---|
| Skill_01 | 单次近战 | 伤害、范围、命中时机 |
| Skill_02 | 多段近战 | 段数、每段倍率、段间隔 |
| Skill_03 | 扇形横扫 | 扇形角度、半径、伤害 |
| Skill_04 | 突进攻击 | 距离、速度、碰撞与命中规则 |
| Skill_05 | 单发直线投射物 | 速度、寿命、伤害 |
| Skill_06 | 扇形多发投射物 | 数量、夹角、单发伤害 |
| Skill_07 | 追踪投射物 | 目标规则、追踪强度、速度 |
| Skill_08 | 穿透投射物 | 穿透次数、同目标去重、衰减 |
| Skill_09 | 自身范围爆发 | 半径、伤害、击退 |
| Skill_10 | 目标位置范围打击 | 选点规则、预警时长、半径 |
| Skill_11 | 持续伤害区域 | 持续时间、跳伤间隔、半径 |
| Skill_12 | 直线范围打击 | 长度、宽度、命中时机 |
| Skill_13 | 自身治疗 | 数值／百分比、消耗、冷却 |
| Skill_14 | 范围治疗 | 友方筛选、半径、治疗量 |
| Skill_15 | 限时护盾 | 护盾量、持续时间、吸收规则 |
| Skill_16 | 防御强化 | 减伤／防御加成、持续时间 |
| Skill_17 | 攻击强化 | 攻击加成、持续时间、叠加规则 |
| Skill_18 | 移速强化 | 移速加成、持续时间、叠加规则 |
| Skill_19 | 范围减速 | 减速比例、半径、持续时间 |

共用近战、投射物、范围、增益等执行基类，差异放在数据中，避免复制 20 份相似逻辑。玩家和 AI 使用统一目标数据结构：目标 Actor、目标位置与朝向；玩家由视角／锁定产生，AI 由感知目标产生。没有目标时按技能规则取消或使用前方默认点。

第一轮测试可使用基础几何体、现有动画和占位特效。最终美术、动画与用户命名另行配置；不把逻辑完成等同于最终表现完成。

## 6. 核心流程

### 6.1 器物交互与变身

交互输入 → 查找可交互器物 → 服务器校验距离、视线、存活状态和器物配置 → 解锁或读取形态进度 → 结束需要取消的旧技能 → 替换四技能组 → 重算属性 → 同步外观与 UI。

器物 Actor 提供可配置模型、形态引用和交互距离；可复用交互接口，为后续宝箱、商店等交互预留入口。客户端只发送交互请求，不能直接提交任意形态解锁。

### 6.2 击杀获取经验

服务器结算伤害 → 生命从正值跨越至零 → 死亡流程只执行一次 → 从伤害上下文解析攻击者／投射物拥有者 → 找到玩家钱包 → 发放怪物配置的经验 → 通知 UI。

必须修复伤害来源归属，确保近战、投射物、持续伤害均能正确归属。持续伤害攻击尸体、重复动画命中或网络重复回调不能重复发奖。环境伤害与无法归属的击杀默认不发给玩家。

### 6.3 购买进化／等级／属性

UI 选择商品 → 发起服务器请求 → 校验商品属于允许购买目录、前置条件、等级上限和余额 → 验证可应用配置 → 一次性扣款并增加等级 → 重算受影响属性／技能 → 同步余额和结果。

使用结果枚举区分成功、余额不足、已满级、前置条件不足、配置无效、当前状态禁止等情况。失败不能扣款；连续点击不能突破上限或得到负余额。客户端不得提交价格、收益或自行增加经验。

### 6.4 属性计算

属性最终值按明确顺序计算：当前人形／形态阶段基础值 → 永久购买加成 → GAS 临时效果 → 范围限制。

最大生命、最大法力、攻击、防御、伤害倍率和移动速度统一进入属性／效果体系；不使用每次切换直接累加的做法。护盾需要独立属性和伤害吸收顺序。临时增益到期可自动移除。

伤害统一由服务器结算：基础伤害与技能等级 → 攻击者加成 → 目标防御／减伤 → 护盾吸收 → 扣生命 → 死亡与经验奖励。治疗独立处理，不能被伤害倍率误放大。

## 7. UI 与蓝图可用接口

- 查询：经验余额、当前形态／档位、已解锁形态、四槽技能、冷却、技能等级、商品价格、能否购买。
- 操作：交互、切换已解锁形态、恢复人形、购买下一档进化、购买技能等级、购买属性等级。
- 事件：余额变化、形态变化、技能组变化、购买成功／失败、解锁形态。
- 第一版提供最小可操作测试界面：经验显示、四技能显示、交互提示、进化与属性商品按钮。
- 输入按 Enhanced Input 资产配置，不写死最终按键；第四技能按键待配置，测试可暂用数字键。

## 8. 同步与保存

1. 经验、解锁、购买与伤害由服务器负责，UI 读取复制后的状态。
2. 其他客户端能看到形态与施法表现；钱包和购买明细优先仅同步给拥有者。
3. 进度放在 PlayerState 关联组件中，角色重生重新绑定 GAS 和技能组，防止重复授予。
4. PlayerState 持有不等于退出游戏后自动保存。单机持久化另用 SaveGame，按稳定 ID 保存经验、形态档位及购买等级，载入时校验上限与失效资源。
5. 初版目标覆盖单机和监听服务器基本同步；联网正式持久化、账号后台与跨服务器数据不在本轮范围。

## 9. 分阶段交付顺序

### 阶段一：基础与四技能

- 核对现有蓝图的技能、效果、命中和死亡流程。
- 实现技能定义、四槽技能组、统一触发入口和第四输入。
- 玩家和怪物各使用一套四技能测试组，验证授予、撤销、冷却和 AI 触发。

### 阶段二：经验货币与购买

- 实现钱包、购买目录、等级记录、服务器交易与 UI 事件。
- 修复击杀归属及重复奖励，接入怪物经验奖励。
- 打通一个属性商品和一个技能等级商品。

### 阶段三：器物变身与三档进化

- 实现器物交互、形态解锁、切换与人形恢复。
- 一个示例形态配置三档，每档四技能及不同数值。
- 打通进化购买、百分比保持、外观同步和重生恢复。

### 阶段四：扩充 20 技能

- 按近战、投射物、范围、治疗与状态效果分批实现模板。
- 每项提供技能配置、必要 GE／执行资源与玩家、怪物适配。
- 提供示例配置表，用户修改名称、图标、参数和所属技能组。

### 阶段五：界面、保存与回归

- 完成测试 UI、保存／读取及配置校验。
- 验证单机与双客户端场景，整理蓝图接线和配置文档。

## 10. 验收标准

- 玩家四个技能槽都能触发；怪物可根据距离与冷却选择四槽技能。
- 20 个模板各有可运行行为、独立配置和明确失败条件。
- 交互解锁并变身，技能组、属性与外观按配置更新。
- 初级、中级、高级共三档；费用正确、余额不足拒绝、高级不可再进化。
- 击杀每个怪物只奖励一次；投射物和持续伤害归属正确。
- 经验能购买进化、技能等级及属性等级，交易失败不扣款。
- 切换形态保留购买等级，不叠加重复属性，不绕过冷却，不重复回血。
- 死亡与重生后状态可恢复，技能数量不持续增长。
- 保存后重启可恢复经验、形态档位和购买记录。
- 编译通过；针对交易、属性重算、死亡奖励增加必要自动化测试，并执行编辑器内功能验收。无法运行的验证需明确记录。

## 11. 实施时还需确定的配置

这些信息不阻塞框架开发，但影响最终可玩的内容：

- 首批形态数量、形态名称与对应器物模型。
- 三档外观是否不同，以及可用骨架／动画资源。
- 每个形态每档装备的四个技能 ID，以及怪物的四技能组合。
- 20 个技能的最终名称、图标、数值、动画和特效。
- 怪物奖励、升级价格、等级上限和属性收益。
- 最终按键、购买界面入口、保存槽与自动保存时机。

下一步按阶段一开始实施，先完成统一四技能与数据结构，再接入经验和变身闭环。
