# 下一步开发方向

## 程序化地图的下一步

`Plugins/SpiritWFC` 已作为独立模块提供平面与最多三层的 WFC 框架、开源建筑样例和[详细配置/贪心算法文档](../Plugins/SpiritWFC/README.md)。先在自己的场景副本中确认格子大小、Pivot、楼梯开口与角色净高，再配置碰撞/导航并验收实际通行；之后接入口/出口、敌人出生和现有传送系统，最后补规则版本/种子存档。主线三张地图暂不改成随机生成。

## 架构审计后的优先顺序

已核对全部69个C++类、4250个项目资产及当前框架默认配置；结论见[架构审计与优化路线](Architecture/C++架构审计与优化路线.md)。建议先完善经验/铜币变更后的合并保存和退出提交，再统一新旧伤害/阵营规则、集中技能机制参数，之后整理NPC公共层与正式UI。5个旧类只是清理候选，未删除；后端仍是预留适配层，正式菜单为壁画版，文字版只作回退。

本轮已修复控制器输入副本释放、旧F1–F12调试键的发布限制、旧近战通知的Shipping编译问题，并移除3个无用头文件依赖。Editor/Game Development与Shipping编译通过；未运行游戏或修改关卡、蓝图、存档。

更新日期：2026-10-24。测试入口保持L_FlatTestArena。完整状态见[完整说明](完整功能更新与配置说明.md)，最新功能配置见[真实技能与铜币](真实技能与铜币配置.md)。

## 先联调战斗与美术

| 优先项 | 配置入口 | 验收重点 |
|---|---|---|
| 技能手感/平衡 | Skills/Design、SkillDefinition | 距离、伤害/控制、前摇、CD、蓄力松开与取消 |
| 正式表现 | Form Stage、Locomotion、Cast/Impact/Projectile特效 | 给不同技能替换专用动作、方向、音效；避免旧AnimNotify重复伤害 |
| 常驻战斗HUD | CurrentSlots、GetCooldownRemaining、OnLoadoutChanged | 真实四槽图标、冷却、法力、施放反馈与实际改键 |
| 新技能页 | DA_SkillGallery.ExecutableSkill与美术字段 | 改图不改身份，未解锁灰显，装备等服务器结果；恢复当前形态组 |
| 场景拾取 | BP_CopperCoin、BP_ExperiencePack、Artifact组件 | 碰触只结算一次、音频正常、不同奖励不互相误触发 |
| 数值曲线 | CombatBalance.Profiles、Upgrade Catalog | 击杀时间、经验获取速度、两档进化费用与精英收益 |

保留初墨独立网格体，材质可自行改黑；陶塑精英仍暂用陶土僧人。正式器物替换方块时保留交互组件与Form引用。迁入LanTu资源用于正式关卡搭建，平地场保留作回归入口。

## 复杂场景与多人专项

当前真实流程按单机PVE实测，不等于多人全部验收。接下来验证两客户端形态/技能/粒子归属，Root与蓄力输入的预测表现，召唤物联机外观与归属、复杂障碍下跟随/牵引、死亡换Pawn、长期反复装备和资源回收。Boss可配置Skills.bControlImmune，正式Boss行为另做。

## 明确两种货币与存档业务

本地v3保存经验、铜币、力量/档位、形态、商品与手动技能组；键位另存。后端现只保存经验，尚无铜币云存储、账号归属或自动同步。

下一步确定权威来源和稳定角色ID，在奖励/消费前加载；变化标脏，排队/节流保存；处理断网、重复请求、409版本冲突及退出策略。完整云档须一次性覆盖购买记录与两种货币，不能拼接任意本地进度和单独云经验。铜币商品/兑换规则待设计确定后再接。

父类入口：[69个C++类索引](CPP父类配置索引.md)、[UI接入](UI操作与UMG接入配置.md)、[后端框架](../Backend/README.md)。GitHub通过SSH同步，二进制资源使用Git LFS。
